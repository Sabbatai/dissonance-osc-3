Make your own instrument with an LLM

You do not need to know JavaScript. The safest method is to give the LLM a working Dissonance instrument and ask it to change the musical idea while preserving the workshop plumbing.

1. Download a starter. Use one of the Download HTML buttons above. Dissonance is the simplest general starting point; use FX if you want to process somebody else's sound.
2. Give the file to an LLM. Start a new chat, attach the downloaded .html file, and describe the instrument you want to make.
3. Paste the prompt below. Replace the bracketed sentence with your own idea. Ask the LLM to return one complete HTML file.
4. Test it. Open the generated HTML while connected to this Dissonance server. Check that Start sound, send audio, routing controls, and your new musical controls work.
5. Share it. Go to Post your instrument, upload the HTML, then find it in the gallery.
Recommended prompt 
This HTML file is a working instrument for a collaborative networked music system called Dissonance.

Please transform it into this instrument:
[DESCRIBE THE INSTRUMENT YOU WANT HERE]

Keep it compatible with the existing Dissonance workshop system. Important rules:

1. Return ONE complete, self-contained HTML file.
2. Keep these shared scripts and use the existing Dissonance helpers. Do not replace the networking layer:
   <script src="osc-browser.min.js"></script>
   <script src="dissonance.js"></script>
3. Use audioContext() instead of creating a new AudioContext.
4. Connect the instrument's final sound to audioOut(), not directly to ctx.destination. This preserves "send audio", "my speakers", and Stop/Resume sound.
5. Register useful musical controls with param(). This gives them Dissonance routing strips so other participants can send control values to them or receive their values.
6. For an effect that receives another participant's audio, use audioIn() rather than building a separate streaming system.
7. For sequencers, clocks, repeating events, or delayed musical actions, use bgInterval(), bgTimeout(), clearBg(), and lookahead() rather than ordinary setInterval()/setTimeout() when practical.
8. Do not remove the participant name field, connection status, routing UI, send-audio controls, or existing Dissonance infrastructure unless there is a very good reason.
9. Do not add external libraries, CDNs, build tools, npm dependencies, or extra files. Everything specific to the new instrument should live in this HTML file.
10. Keep control traffic moderate. Do not send high-rate parameter updates unless musically necessary. For LFOs or continuously generated controllers, use param() with maxHz and epsilon so network control messages are throttled and tiny changes are suppressed. A reasonable starting point is maxHz: 10 and epsilon: 0.01.
11. Incoming Dissonance control values should change the sound exactly as local control gestures do. Do not create a second disconnected set of controls.
12. Preserve any working networking/audio code from the starter wherever possible. Make the smallest changes needed to create the new instrument.

Before returning the file, check that all element IDs referenced by JavaScript actually exist and that Start sound can only initialize the audio graph once.

Return only the complete HTML file, ready to save and post to the Dissonance gallery.

Ideas to try

Transform a synth“Turn this into a noisy resonator with three frequency bands, feedback, decay, and excitation controls.”
Make a controller“Turn this into four independent LFOs with rate, depth, waveform, and phase controls. The LFO outputs should be routable to other instruments.”
Make an effect“Turn this into a strange pitch-and-delay processor that receives another participant's audio and has routable feedback, pitch spacing, and delay controls.”
Make something unruly“Make a swarm instrument with 12 unstable oscillators controlled by fundamental pitch, spread, swarm size, and chaos.”
If the generated instrument breaks: give the LLM the last working HTML again and ask it to make a smaller change. The Dissonance networking and audio code is already working, so it is usually better to preserve it than to rewrite it.
